# Plot Reasoning

## Purpose

Turn a story question into a concrete, traceable, forward-moving plot exploration. Do not merely judge plausibility; generate actions and test how their consequences reshape the next choice.

## 1. Define the exact task

Identify:
- focal character/event;
- story time and current scene state;
- requested scale;
- what the author wants to achieve or preserve;
- what must remain undecided.

Do not broaden a local question into a volume outline.

## 2. Establish the starting state

Extract only relevant, sourced facts:
- immediate and longer-term goals;
- knowledge, beliefs, suspicions and misunderstandings;
- established motive and emotional/relational context;
- capabilities, resources, access and constraints;
- current location and ongoing activity, if known;
- other actors' known goals and information;
- events already occurred;
- unresolved facts affecting feasibility.

Separate objective facts from each character's knowledge and the reader's knowledge.

### The plot-anchor test

Before proposing a sequence, identify at least one concrete anchor:
- a confirmed character goal;
- an unresolved problem the character is already trying to solve;
- an event that has happened and requires a response;
- a concrete external condition that constrains or changes the character's options.

If none is available, do not invent a goal such as “investigate”, “seek the truth” or “verify the anomaly” merely because it is a convenient plot engine. State the missing anchor. Offer conditional directions only if each direction explicitly names the new premise it requires, or ask one essential question.

## 3. Separate premise, deduction and proposal

Use these labels:

- **Confirmed premise**: directly supported by current project authority.
- **Deduction**: follows from confirmed premises without adding a new premise.
- **Plausible action**: the character can take this action, but the source does not establish that they will.
- **Likely choice**: best supported by the character's established goals, knowledge and tendencies; explain why.
- **New plot proposal**: introduces a new event, clue, motive, action, response or condition.
- **Unsupported leap**: necessary causal information is missing.

Never call a plausible action a deduction. Never use a new proposal as a premise for a later “deduction” without keeping the dependency visible.

## 4. Generate actions before events

For each candidate action, specify:
- actor;
- immediate objective;
- why now;
- information relied on;
- tactic/action;
- capability and access required;
- target or affected party;
- possible response;
- expected state change.

A character may choose not to act, delay, conceal, abandon the goal or change tactics. Consider these only when consistent with the character's established state.

An external event without a character choice is possible, but its trigger, source and causal role must be grounded or marked as a new proposal.

## 5. Build the dynamic plot loop

Use:

`State → Perception → Judgment → Choice → Action → Response → Changed State → Reassessment`

Then repeat from the changed state.

For each beat, answer:
1. What triggers this beat?
2. Who acts, and what do they concretely do?
3. What are they trying to change?
4. What information and assumptions guide them?
5. Who or what responds, and why?
6. What actually changes?
7. What remains unchanged?
8. Why does the new state create the next choice?

Do not skip the response or state-change step. If the next beat would happen regardless of the previous one, it is not yet causally connected; either establish the independent trigger or restructure the chain.

## 6. Test the transitions

For every causal link, ask:
- What evidence supports it?
- Does the actor know enough?
- Can the actor do it at this time?
- Is the motive established or newly proposed?
- Is the response attributable to a known actor/condition?
- Does the result actually follow?
- Does it preserve project constraints?
- Does it create a changed state that supports the next beat?

Classify gaps as missing motivation, information, capability, access, trigger, response, consequence, timeline, or rule interaction.

These labels diagnose gaps; they do not authorize filling them silently.

## 7. Design meaningful branches

Branches must differ in a consequential way: tactic, choice, information, response, belief or condition.

For each branch, show:
- divergence point;
- changed choice or premise;
- immediate result;
- next state;
- downstream consequences;
- what the branch requires the author to accept.

Do not manufacture three options when one path is clearly grounded. Do not create superficial variants that lead to the same result.

## 8. Compare paths

Compare by:
- fit with character goals and established behavior;
- character agency;
- causal continuity;
- dramatic tension and scene potential;
- meaningful state changes;
- new choices opened or closed;
- information and reveal control;
- dependencies on unresolved decisions;
- continuity cost.

Recommend the best-supported path, not automatically the most spectacular one. Explain trade-offs and uncertainty.

## 9. Output

A useful result usually contains:
- starting anchor and source;
- current character state;
- one primary action path in concrete beats;
- feedback and state changes after each beat;
- optional branches where they matter;
- new premises explicitly labeled;
- unresolved gaps and the single most important author decision.

Do not pad the answer with a long recitation of worldbuilding. Use sources to ground the plot, then spend the response on what characters do and what happens next.
