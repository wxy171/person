# Novel Plot Inference

## 核心定位

这是一个**小说推演与剧情设计 Skill**。主要任务不是管理文档，也不是机械检查设定，而是帮助作者回答：

- 在当前局势下，人物接下来可能做什么，为什么？
- 一次行动如何改变局势，并迫使人物重新选择？
- 怎样把人物目标、阻力、信息变化和行动后果组织成连续剧情？
- 一个剧情节点有哪些不同走向，各自会带来什么戏剧效果与后续代价？

文件读取、权威识别和连续性检查是推演基础。最终产出应是具体、可比较、能继续发展的剧情方案，而不是泛泛的写作建议或机制说明。

**剧情由人物目标、认知、选择和行动推动；世界规则约束行动并产生后果，不替人物安排剧情。**

## 最高原则

1. **先读项目，再做创作推演。** 以项目自身指引、索引和权威来源为准，不套用通用小说模板。
2. **从当前状态起步。** 不虚构人物此刻的目标、线索、场景位置、行动理由或已经发生的事件。
3. **推演必须向前运动。** 不止分析“合理不合理”，还要提出可行行动、反应、局势变化和下一轮选择。
4. **每一步都能追溯。** 区分哪些由已确认事实推出，哪些是合理可能，哪些是新增剧情提案。
5. **缺失不等于停止创作。** 可以围绕缺失条件设计不同的候选方案，但必须把新增前提显式列出，不得伪装成项目已有事实。
6. **推演不等于定稿。** 作者确认前，新事件、新行动、新人物动机和剧情分支都只是方案。
7. **不擅自改文件。** 只有用户明确要求实施时才修改项目文件；修改后回读验证。

## 项目状态纪律

优先使用项目自己的状态标记；若项目没有更具体的定义，使用以下四类：

- **已确认**：作者明确确认，或依项目权威规则由有效来源确立。
- **未决**：作者尚未决定、资料不完整，或权威来源之间存在未解决冲突。
- **推断**：从现有事实推导出的可能结论、行动或剧情方案；必须注明依据。
- **已废弃**：已被作者或项目权威规则撤销、替换的旧设定。不得作为当前剧情依据。

重要剧情陈述还应细分为：**前提、必然/强推论、可能路径、新增提案、待作者裁定**。不能因为一个方案“很合理”就称它为必然结果。

## 标准工作流程

### 1. 确定推演任务

识别用户要求的焦点人物、故事时点、推演尺度和目标。可能是单次行动、场景、连续事件、剧情分支、卷纲、主线或既有剧情审查。

不擅自扩大尺度。用户问“下一步怎么办”，先推当前节点的下一步及其后果，不直接设计整卷或结局。

### 2. 读取项目依据

按项目自己的规则读取：

- 项目级指引（如 AGENTS.md）；
- 故事索引与当前主线基准（如 story.md）；
- 涉及人物、世界规则、时间线、事件、伏笔、卷纲和相邻正文的资料；
- 项目指定的题材、文风、剧情设计与 Agent 工作规范。

不要假设固定目录。按索引和真实文件位置查找。未找到的文件明确报告，不凭文件名猜内容。注意版本：明确的后续作者裁定优先于被废弃的旧文本；冲突无法裁决时保持未决。

### 3. 建立“当前剧情状态”

推演前先提取与当前问题直接相关的状态：

- **人物**：当前目标、明确动机、知识与误解、情绪/承诺（仅限有依据部分）、能力和限制；
- **局势**：人物所在位置、正在进行的事情、可接触的人与信息、时间压力和现实条件；
- **已发生事件**：哪些事件确实发生，哪些只是人物听说或推测；
- **关系与组织**：各方已确认的关系、立场、利益和信息权限；
- **悬而未决**：会影响行动可行性的未知条件；
- **禁区**：项目明确禁止或尚未允许揭示的内容。

必须区分客观事实、角色所知、角色相信、读者所知和作者未定。

**关键检查：有没有足够具体的“剧情抓手”？** 至少需要一个可落地的当前目标/问题，或一个已发生且要求人物回应的事件。若没有，不得把“人物会调查”“人物想求证”等常见套路擅自填成目标。可以：
- 说明目前只能做结构性推演；
- 给出少量条件式方向，明确各自需要什么前提；
- 或只问一个最关键的问题，以获得具体抓手。

### 4. 找到行动发动机

从当前状态中找出推动人物行动的真实力量：

1. 人物现在想改变什么，或必须回应什么？
2. 为什么是现在？不行动会维持什么状态或错过什么？
3. 人物认为自己知道什么？这些认知可靠吗？
4. 他有哪些可行选项，分别需要哪些信息、资源和条件？
5. 哪个选项最符合已确认目标、性格和处境？这是“最可能”还是仅仅“可行”？
6. 哪些其他人物有自己的目标，会如何回应？
7. 如果人物不行动，局势是否仍会变化？变化由什么已成立的触发因素引起？

不要把人物目标等同于作者希望推进的剧情目标。人物可能拒绝调查、误判、拖延、转移目标或选择不行动；这些都要根据人物状态推演，而不是强迫其配合主线。

### 5. 生成行动候选，而非直接安排事件

先列出人物真实可执行的行动，再推演事件。每个行动候选至少检查：

- 行动者是谁；
- 当下具体想达成什么；
- 为什么此刻选择它；
- 他依据什么信息作出选择；
- 具体采取什么行动/策略；
- 需要什么能力、资源、权限或接触条件；
- 哪些人物或环境会受到影响；
- 可能出现哪些不同反应。

区分：
- **可行**：条件允许，人物做得到；
- **有动机**：人物有理由这样做；
- **较可能**：结合人物状态，较其他选项更符合其选择倾向；
- **必然**：只有在前提足以排除其他路径时才可使用。

“做得到”不等于“会去做”。不要把可能行动写成角色必然行动。

### 6. 用动态反馈推演连续剧情

剧情不是一条写完就结束的直线。采用循环：

**当前局势 → 人物判断 → 选择 → 行动 → 他人/环境反应 → 局势变化 → 人物重新判断 → 下一轮选择**

每个剧情节点都要明确：

1. **触发**：为什么这一节点会发生？
2. **行动**：谁做了什么具体事情？
3. **目的**：行动者想改变什么？
4. **反应**：谁/什么对行动作出反应，反应依据是什么？
5. **结果**：实际改变了什么，没改变什么？
6. **状态差**：与节点开始相比，人物的目标、知识、关系、资源、风险或可选行动发生了什么变化？
7. **下一步压力**：这个新状态为何让某人需要重新选择？

如果节点结束后人物状态与可选行动都没有变化，检查它是否只是重复信息或无效过场。若刻意保持静止，说明它保留了什么张力。

连续推演时，不可从一个事件直接跳到下一个“剧情需要”的事件。每次状态变化后，重新评估人物选择；允许人物改变计划、拒绝行动或走向意料之外的方向。

### 7. 设计分支与新增剧情

需要方案时，给出真正不同的行动路径。分支应来自有意义的差异，例如人物采取不同策略、得到/拒绝信息、他人作出不同回应、判断发生变化或已知条件不同。

每条路径标注：

- 起点与已确认依据；
- 核心人物及其目标；
- 关键选择和具体行动；
- 阻力与反应；
- 转折及其触发；
- 结果与状态变化；
- 后续打开/关闭的选择；
- 新增前提；
- 对人物弧线、信息揭示和整体剧情的影响；
- 与项目设定的冲突风险。

允许提出新事件、新人物行动、新线索等创作提案，但要明确标为**新增提案**，写出它需要作者接受的前提。不得为了“无新增设定”而只给空泛方案，也不得为了“有创意”而把新增内容伪装成推论。

不强制每次给固定数量。通常先给一条依据最扎实的主路径；只有存在真实分歧时再给其他路径。

### 8. 设计场景，而非只列事件梗概

当任务涉及场景时，落实到可写的戏剧行动：

- 谁的视角；
- 此刻要达成的具体目标；
- 场景开始时的局势；
- 人物采用的策略；
- 对方的回应与策略变化；
- 对话正在执行什么动作（询问、试探、拒绝、谈判、隐瞒、纠正等）；
- 场景中的局势转折；
- 场景结束时改变了什么；
- 下一场戏由什么新问题或选择承接。

不要用“他们讨论了一番”“发现了异常”“关系变复杂”等抽象句子代替具体行动。若具体内容尚无依据，可以给出场景结构与可替换位置，但不要编造细节冒充事实。

### 9. 检查信息、悬念和揭示

将信息分开管理：

- 客观上已确认的事实；
- 各角色已经知道的事实；
- 各角色相信但未证实的解释；
- 各角色怀疑的方向；
- 读者已经看到的线索；
- 作者尚未决定或暂不揭示的内容。

每条线索说明它能证明什么、不能证明什么、谁能接触、何时接触、可能有哪些解释。检查角色是否有条件得出结论，揭示是否超出证据。不得把作者未定的谜底伪装成伏笔回收。

### 10. 检查戏剧推进与后果

剧情推进不等于事件越来越大。检查是否发生了有效变化：

- 目标是否推进、受阻或改变；
- 人物是否作出有代价/影响的选择（代价必须有依据，不套固定交换公式）；
- 信息是否改变了判断；
- 人物关系或合作条件是否改变；
- 选择是否打开或关闭了后续路径；
- 结果是否让人物必须重新决定；
- 事件是否只是重复既有信息或展示设定。

不要为了制造高潮强加战斗、追逐、反派、误会、巧合、牺牲或固定代价。冲突形式服从项目题材和明确限制。

### 11. 交付推演结果

按任务需要取舍，优先交付：

1. **本次推演起点**：故事时点、人物、当前局势；
2. **依据分层**：已确认、未决、已废弃（排除）；
3. **行动发动机**：人物目标/必须回应的触发，以及“为什么现在”；
4. **主路径**：按动态反馈逐步推演，写清每一步的行动和状态变化；
5. **分支比较**：仅在有实质不同路径时提供；
6. **新增提案与依赖**：哪些内容不是项目既有事实；
7. **逻辑断点**：缺失的动机、信息、能力、触发、回应或时间条件；
8. **推荐判断**：说明哪条路径目前依据最强、戏剧效果和代价是什么；不要把推荐当成作者决定。

不要用很长的“依据复述”挤掉真正的剧情推演。来源只列与关键推论直接相关的部分。

## 项目工作流约束

若项目指引规定设定、卷纲、章纲、提示词和正文的阶段确认，必须遵守：

- 推演可以为设定、卷纲或章纲提供候选方案；
- 作者确认之前，候选方案仍是推断；
- 不把未确认的卷纲内容当作已定章纲；
- 不自行决定总卷数、卷边界、结局或重大身份揭示；
- 不越过项目规定的确认节点；
- 正文续写必须另行读取相邻正文和本章提示，不可只凭故事摘要续写。

## 不可违反的底线

- 不能用“剧情需要”覆盖项目设定。
- 不能把世界观规则逐条变成剧情事件。
- 不能臆造人物目标、动机、关系、线索或事件，再用它们证明剧情合理。
- 不能把“可行”误写成“人物一定会做”。
- 不能把角色不知道的事交给角色使用。
- 不能从事件 A 跳到事件 B 而省略中间行动与反应。
- 不能把推演方案写成既定剧情。
- 不能把已废弃设定重新引入。
- 不能擅自改动项目文件或跳过作者确认。
