# Terminology Management

## Purpose

Keep terms stable, precise, and distinguishable across a project, especially when definitions evolve.

## 1. Build a term record from project evidence

For each important term, identify:

- current preferred form;
- current definition;
- scope and exclusions;
- concepts it is often confused with;
- explicit distinctions from similar terms;
- source that governs the definition;
- aliases and spelling variants;
- former definitions and rename history, if documented;
- status: current, unresolved, deprecated, or historical quotation.

Do not assume that a glossary is authoritative unless the project says so.

## 2. Distinguish neighboring concepts

For terms that appear similar, compare:

- what each term names;
- what entities or events it applies to;
- whether each describes a state, process, cause, result, or interpretation;
- whether one can occur without the other;
- whether their conditions and outcomes differ;
- whether the project explicitly says they are equivalent or distinct.

Do not collapse terms because they sound synonymous. Do not create a distinction that the author has not established; label it as a question or proposal.

## 3. Handle renames and definition changes

A terminology change may involve one or more separate operations:

1. rename only; definition remains the same;
2. revise the definition; name remains the same;
3. split one concept into multiple concepts;
4. merge concepts;
5. deprecate a concept;
6. introduce a new concept that resembles an existing one.

Identify which operation the author intends. If unclear, ask rather than assuming.

A rename does not prove that the underlying mechanism changed. A changed definition does not necessarily authorize a global rename.

## 4. Audit references without blind replacement

Search all likely references, including:

- current setting files;
- character descriptions and dialogue;
- timeline and summaries;
- indexes, appendices, examples, and cross-links;
- historical notes and quoted passages.

Classify each occurrence:

- current use that should follow the new definition;
- stale use that contradicts the current definition;
- intentional historical wording;
- quotation of an earlier version;
- ambiguous use requiring author review;
- unrelated homonym or ordinary-language use.

Never perform a global find-and-replace without checking context. Preserve historical quotations when appropriate and label them clearly if the project requires it.

## 5. Detect terminology drift

Flag cases where:

- one term has multiple incompatible definitions;
- multiple terms are used for the same concept without an alias rule;
- a term's scope silently expands or narrows;
- an old name remains in current explanatory prose;
- a definition uses another term in a way that changes its meaning;
- prose uses a term in a way inconsistent with its governing definition.

A single unusual occurrence is not enough to prove drift; inspect its context.

## 6. Suggested change record

When the project has no established format, propose—not automatically impose—a compact record:

- Term:
- Previous form / definition:
- New form / definition:
- Change type:
- Author decision or source:
- Affected files:
- Historical occurrences to preserve:
- Remaining questions:

## 7. Editing checklist

- [ ] The intended type of terminology change is clear.
- [ ] Current and historical definitions are not conflated.
- [ ] Similar terms retain their documented distinctions.
- [ ] Every occurrence was assessed in context.
- [ ] Intentional quotations and historical references were preserved.
- [ ] Indexes and dependent documents were checked.
- [ ] No unrelated terms were changed.
