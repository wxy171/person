# Cross-File Consistency

## Purpose

Find and explain inconsistencies across a novel project without overstating evidence or silently deciding how conflicts should be resolved.

## 1. Build a dependency map

For the subject being checked, search for:

- its primary definition or profile;
- indexes and summaries;
- references from other setting files;
- timelines and event records;
- character knowledge and relationship records;
- examples, appendices, and manuscript passages;
- earlier names and deprecated descriptions.

Use explicit links and project indexes where available. Search aliases and distinctive phrases when links are incomplete. Do not assume that every file mentioning a term is authoritative for it.

## 2. Classify findings

Use these categories:

| Category | Meaning |
|---|---|
| Direct conflict | Two applicable claims cannot both be true under the same scope and time |
| Scope mismatch | Claims differ because they govern different contexts or domains |
| Temporal mismatch | Claims may describe different points in the timeline |
| Perspective mismatch | A character's belief or report differs from objective setting information |
| Terminology drift | A term's usage or definition has changed inconsistently |
| Synchronization omission | A confirmed change has not been reflected in a dependent source |
| Potential conflict | A statement may cause a contradiction, but available evidence is insufficient |
| Information gap | The project does not specify a fact needed to decide |
| Stale reference | A source still uses a superseded definition outside a deliberate historical context |

Do not classify a potential conflict or information gap as a direct contradiction.

## 3. Evidence format for each finding

Provide:

- **ID**: stable short label for the report;
- **Type**: one category above;
- **Sources**: exact paths and headings or line locations;
- **Statements**: concise, faithful summaries of the relevant claims;
- **Why it matters**: the logical or continuity consequence;
- **Confidence**: direct evidence, strong inference, or uncertain;
- **Resolution status**: resolved by project rule, unresolved, or author decision required.

Use exact quotations only when needed. Do not fabricate line numbers or claim to have read files that were not accessible.

## 4. Impact analysis after a proposed change

For each proposed change, inspect:

- direct references to the changed term, character, event, or rule;
- dependent definitions and examples;
- character knowledge and motivation;
- event order and timeline;
- relationship descriptions from other perspectives;
- summaries and indexes;
- manuscript passages that rely on the old version.

Classify each file as:

- must change;
- should review;
- no change needed;
- cannot determine from available evidence.

Explain the reason for each classification. Do not edit every file merely because it contains the same keyword.

## 5. Distinguish conflict from intentional complexity

Before reporting a contradiction, test whether the difference is explained by:

- different time points;
- limited character knowledge;
- unreliable testimony;
- different scopes or levels of description;
- an explicitly allowed exception;
- a deliberate mystery or unresolved question;
- a historical version quoted for context.

Do not use "mystery" as a blanket excuse for incompatible rules. If the documents do not establish whether a discrepancy is intentional, report it as unresolved.

## 6. Prioritize findings

A useful default order is:

1. conflicts affecting core definitions or major causal dependencies;
2. timeline, identity, or character-knowledge contradictions;
3. relationship and status inconsistencies;
4. terminology drift and stale references;
5. index, summary, and formatting omissions.

This is a reporting order, not an authority hierarchy. Adjust it to the user's task.

## 7. Final audit checklist

- [ ] Relevant sources and aliases were searched.
- [ ] Source authority and scope were checked.
- [ ] Time and perspective differences were considered.
- [ ] Direct conflicts are separated from potential conflicts.
- [ ] Every finding has traceable evidence.
- [ ] Proposed fixes do not introduce unsupported canon.
- [ ] All dependent files were assessed.
- [ ] Unresolved author decisions are explicit.
